## 1. Executive Summary

As an educational decision intelligence platform handling records of minor students, teachers, parents, and administrative staff, EduIntel processes significant volumes of **Personally Identifiable Information (PII)** and sensitive financial and academic data.

This assessment inventories all PII across the platform, evaluates compliance with the **Digital Personal Data Protection (DPDP) Act 2023 (India)** and **GDPR**, analyzes privacy leakages in existing logs and APIs, and defines data minimization, retention, and deletion architectures.

## 3. Privacy Defect & Leakage Analysis

### 3.1. Audit Log Plaintext Query Leakage (SEC-13)
- **Defect:** In [`backend/app/observability/service.py:126`](file:///home/dell/projects/eduIntel/backend/app/observability/service.py#L126), `log_ai_query` records raw `query_text` into the `audit_logs` table:
  ```python
  log = AuditLog(
      user_id=user_id,
      endpoint=endpoint,
      query_text=query_text, # UNREDACTED!
      was_blocked=was_blocked,
      ...
  )
  ```
- **Privacy Impact:** Although [`backend/app/guardrails/pii_redaction.py`](file:///home/dell/projects/eduIntel/backend/app/guardrails/pii_redaction.py) redacts PII from agent *outputs* (e.g. parent report emails), the user's *input* query is stored verbatim in the database. If a student or teacher enters an email, phone number, or guardian name into the prompt, it persists indefinitely in `audit_logs`.
- **Remediation:** Pass `query_text` through `redact_pii(query_text)` before writing to `audit_logs`, or mask detected regex patterns with `[REDACTED_PHONE]`, `[REDACTED_EMAIL]`.

### 3.2. Unauthenticated Parent Report Leakage (SEC-03)
- **Defect:** [`backend/app/reports/router.py:18`](file:///home/dell/projects/eduIntel/backend/app/reports/router.py#L18) allows any unauthenticated HTTP client to supply a student UUID and an external email address.
- **Privacy Impact:** Proprietary student academic evaluations (exam scores, attendance rates, weak subject topics) are generated by Gemini/Groq and transmitted over cleartext SMTP to arbitrary email addresses without guardian verification.
- **Remediation:** Enforce authentication and restrict recipient addresses strictly to `StudentProfile.parent_email`.

### 3.3. Cross-Tenant Guardian Contact Exposure (SEC-04)
- **Defect:** `GET /admin/students` returns all student profiles across the database.
- **Privacy Impact:** Any administrator can view phone numbers, physical addresses, and guardian contact information for students in competing institutions.
- **Remediation:** Enforce multi-tenant Row-Level Security (RLS) so administrators can only view students enrolled in their institution.

### 3.4. Unencrypted Flat File Storage
- **Defect:** Student homework files are written to `backend/uploads/homework/` using predictable UUID filenames on the local filesystem.
- **Privacy Impact:** Files are unencrypted at rest and stored in a shared directory across all institutions.
- **Remediation:** Organize uploads by tenant prefix (`uploads/{institution_id}/homework/...`) and implement server-side encryption at rest (AWS S3 SSE-S3 / SSE-KMS in Phase 8).

## 4. Regulatory Compliance Framework (DPDP Act 2023 & GDPR)

### 4.1. Processing of Children's Data (DPDP Act 2023, Section 9)
EduIntel processes data of students under 18 years old. The law mandates:
1. **Verifiable Parental Consent:** The institution must obtain explicit consent from parents/guardians before creating student profiles and processing academic data.
2. **Prohibition of Tracking & Behavioral Profiling:** Educational analytics and ML models (e.g. XGBoost At-Risk predictions) must strictly serve educational remedial purposes and must not be repurposed for commercial targeting.

### 4.2. Data Minimization & Purpose Limitation
- The platform must collect only data strictly necessary for academic administration.
- Optional fields (e.g. physical home address, guardian telephone 2) should be clearly marked as optional or eliminated if not operationally essential.

### 4.3. Data Retention & Archival Policies

| Category | Recommended Active Retention | Archival Policy | Destruction Procedure |
|---|---|---|---|
| **Student Profiles & Grades** | Duration of student enrollment + 1 academic year | Cold archive for 3 years (legal requirement for transcripts) | Cryptographic deletion / purge from database |
| **Attendance Records** | Current academic year | Aggregate monthly summaries retained; daily rows purged after 1 year | Hard delete via scheduled batch job |
| **Homework Files & Images** | Current semester (6 months) | Delete physical files; retain grade and feedback text | Secure file unlink from disk/S3 |
| **AI Audit & Trace Logs** | 90 days | Export anonymized statistical metrics; purge raw rows | Rolling 90-day partitioned table purge |
| **Password Reset Tokens** | 30 minutes | Expired/used rows purged after 24 hours | Automated daily cleanup task |

## 5. Tenant-Specific Data Export & Deletion Procedures

In a multi-tenant SaaS platform, when an institution terminates its subscription, or when an individual exercises their Right to Erasure, the platform must provide automated data portability and deletion:

### 5.1. Tenant Data Export (`Tenant Export Bundle`)
A secure endpoint for Platform Administrators and verified Institute Owners:
- **Format:** Encrypted `.tar.gz` containing:
  - `database_dump.json`: All records where `institution_id = :id` across all 17 tables.
  - `files/`: All uploaded homework and study materials under `uploads/{institution_id}/`.
  - `vector_embeddings/`: Export of all ChromaDB chunks tagged with `institution_id`.

### 5.2. Tenant Hard-Delete (Cascade Purge Protocol)
A controlled, audited hard-delete operation:
1. Set `institutions.is_active = FALSE` (immediate suspension of all tenant logins).
2. Execute cascading deletion in PostgreSQL:
   ```sql
   DELETE FROM institutions WHERE id = :institution_id;
   -- Cascades automatically to users, profiles, assignments, submissions, attendance, etc.
   ```
3. Purge vector embeddings from ChromaDB:
   ```python
   collection.delete(where={"institution_id": str(institution_id)})
   ```
4. Recursively delete physical files:
   ```python
   shutil.rmtree(f"uploads/{institution_id}", ignore_errors=True)
   ```
5. Emit cryptographic audit log proving completion of tenant deletion.
